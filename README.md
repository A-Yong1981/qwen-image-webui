# Qwen 生圖工作台

在自己家飛牛 NAS 上跑的生圖網站。打開網頁，輸入一句話，點生成，圖跑完就顯示在頁面上，還能下載、看歷史記錄。

背後用的是 Kaggle 免費 GPU（T4 x2），模型是 Qwen-Image-2.1 GGUF 輕量版。這條路已經實測跑通過：一張 768×768 的圖，整個任務約 4 到 5 分鐘，生圖本身約 80 秒，燒 GPU 約 269 秒。

## 這個網站有什麼

- 生圖頁：大文字框輸提示詞（中文就可以），點生成，頁面每 10 秒刷新狀態，跑完大圖直接顯示、可以下載。頂部有一塊「伺服器狀態」，顯示已運行時間、Kaggle 連線、額度、排隊與進行中數量、目前任務的提示詞。
- 生圖模式：三段選擇——純文字生圖、單圖參考、多圖參考。參考模式上傳參考圖（jpg、png、webp，每張不超過 10MB，單圖 1 張、多圖最多 4 張），再寫一句話告訴模型怎麼改。提示詞裡用 `<image1>`、`<image2>` 指第幾張圖，例如：把 `<image1>` 裡的人放到 `<image2>` 的海灘上。
- 面板參數：畫面比例（1:1、16:9、9:16、4:3、3:4、3:2、2:3，選了自動填寬高）、寬高（256–1280，步進 16，會按 32 取整）、種子（留空表示隨機，後端會隨機一個並存進記錄）、步數（預設 20，10–50）、引導係數 CFG（預設 1.0，1.0–4.0）、參考強度（只在參考模式顯示，預設 0.7，越大越像原圖）。每個參數下面都有一行白話講解和建議取值。採樣器固定用已驗證的組合（euler / simple），不用改。
- 歷史記錄頁：以前跑過的任務列表，每條都完整顯示當時輸入的原始提示詞（不截斷），點一條看大圖、下載，還可以複製提示詞、或「再用這個提示詞生成」。已完成的記錄可以刪除：卡片上有「刪除」按鈕，詳情裡也可以刪，刪掉的同時圖片檔案也一起刪掉；頂部「清空歷史」一次清掉全部已完成的記錄（排隊中或進行中的任務不會動）。
- 界面是 iOS 清新海地風格：淺色底、淡海水漸變、磨砂白卡片、海藍色按鈕。
- 設定頁：填 Kaggle 用戶名和長期 API 金鑰、測試連線、看 GPU 額度用量；下面還有「修改密碼」區，登入後可以在這裡改密碼。
- 帳號密碼登入：打開網頁先輸帳號密碼才能用。預設帳號 anyong、預設密碼 admin，登入後請到設定頁把密碼改掉。登入憑證 24 小時有效。
- 一次只跑一張，後面的任務排隊等，不會同時燒掉額度。

## 部署到飛牛 NAS

1. 在 GitHub 新建一個空的公開倉庫（例如 `qwen-image-webui`），把這個目錄的檔案推上去。注意：不要把 `data/` 目錄推上去，裡面以後會存你的金鑰和生成的圖。
2. 打開飛牛 NAS 的 Docker，新增一個 Compose 專案，名稱隨便取（例如 `qwen-webui`），建置來源選 GitHub 倉庫，填你的倉庫位址。
3. 飛牛開始建置。第一次建置要下載 Python 映像和安裝依賴，等幾分鐘。NAS 記憶體緊，建置的時候不要同時跑別的建置。
4. 建好、容器起來之後，在 NAS 本機瀏覽器打開 `http://localhost:3100`，能看到生圖頁就表示跑起來了。

## 用隧道域名在外面打開

1. 打開 NAS 的 Cloudflare Tunnel 應用，新增一條 Public Hostname，域名填你想要的（例如 `qwen.aynas.de5.net`），服務指向 `http://localhost:3100`。
2. 等隧道生效後，在任何瀏覽器打開 `https://qwen.aynas.de5.net` 就能用，跟 BeefTV 的做法一樣。

## 登入：帳號密碼

打開網頁會先顯示登入頁，輸入帳號和密碼才能用。

- 預設帳號 `anyong`，預設密碼 `admin`。第一次登入後，請馬上去設定頁「修改密碼」把它改掉。
- 改密碼在設定頁下面：輸目前的密碼、新密碼、再輸一次新密碼，點保存。改完之後要重新登入一次（舊的登入會立刻失效）。
- 帳號密碼只存在 NAS 上的 `/data/auth.json`（權限 600），密碼只存雜湊、不存明文，重建容器也不會丟。

**密碼忘了、進不去了怎麼辦：**在 NAS 的檔案管理裡，到這個專案的 `data` 目錄下刪掉 `auth.json`，再重啟容器（飛牛 Docker 裡點重新啟動），帳號密碼就會恢復成預設的 anyong / admin。之前跑過的任務和圖片都在，不會不見。登入後記得馬上改一個新密碼。

## 第一次使用：先去設定頁填金鑰

1. 打開網頁，點「設定」頁籤。
2. 去 Kaggle 網站 → 設定頁 → API → Create Legacy API Key，下載 `kaggle.json`，裡面有 `username` 和 `key`。
3. 把用戶名和 key 填進設定頁，點保存，再點「測試連線」，顯示連線成功就能用了。
4. 金鑰只存在 NAS 上的 `/data/settings.json`（權限 600），重建容器也不會丟。千萬不要把金鑰發在聊天裡；如果不小心發出去了，去 Kaggle 設定頁重新生成一把，舊的就作廢了。

## 一定要知道的幾件事

- 一張圖大約 4 到 5 分鐘。每次跑都要重新下載 14.23GB 的模型（Kaggle 的暫存區每次跑完就清掉），時間主要花在下載上，生圖本身只要約 80 秒。
- 每週 GPU 額度是 108000 秒（30 小時），按一張約 269 秒算，一週大約能生 400 張。額度每週刷新。
- 提示詞直接傳中文就可以，模型的文字編碼器是多語言的。
- 出圖尺寸可以改：比例選了自動填寬高，也可以手動改寬高（256–1280，會按 32 取整）。建議最大邊不要超過 1024，圖越大跑得越慢、越容易失敗。
- 參考生圖怎麼跑的：參考圖傳到 NAS 後端，存在 `/data/refs/<任務id>/`（任務 id 是隨機的，猜不到，相當於口令），再用公開路由 `/refs/<任務id>/<檔名>` 提供給 Kaggle 內核下載。內核腳本按官方 Qwen-Image-2.1 編輯工作流（Comfy-Org 官方範本 `image_qwen_image_2_1_image_edit`，API 格式見 NewGwen2.1 的 `qwen_image_2.1_gguf_edit_api.json`）拼工作流：`LoadImage` → `TextEncodeQwenImage21`（`images.image_N` + VAE），第一張圖的 latent 決定畫布（內核先按你選的尺寸把第一張圖縮好），`QwenImage21Cache` 接在模型與採樣器之間。官方工作流沒有「參考強度」這個參數，這裡用採樣器的 `denoise` 實現：denoise = 1 - 強度，強度越大越像原圖（預設 0.7 → denoise 0.3）。刪任務、清空歷史時，參考圖會跟著一起刪掉。
- 參考圖在後端會轉成 JPEG、長邊縮到 1024 像素再存；內核下載後第一張圖再按你選的尺寸縮一次。編輯比純文字生圖更吃顯存，T4 上如果出記憶體不足，可以把 `QwenImage21Cache` 的 dtype 從 `default` 改成 `int8`（官方文件說 int8 約等於 bf16 精度、省一半快取）。

## 常見失敗，一句話原因與怎麼辦

| 頁面顯示 | 原因 | 怎麼辦 |
| --- | --- | --- |
| 帳號或密碼不對 | 帳號或密碼輸錯了 | 帳號是 anyong；密碼忘了就刪 data 目錄下的 `auth.json`、重啟容器，恢復成預設密碼 admin |
| 改密碼說目前的密碼不對 | 目前的密碼輸錯了 | 重新輸入目前的密碼；實在想不起來就用上面那招恢復成預設密碼再改 |
| 打開網頁一直要登入 | 登入憑證 24 小時就過期 | 重新登入一次就好 |
| 尚未填寫 Kaggle 金鑰 | 設定頁還沒填 | 去設定頁填用戶名和金鑰，保存後再生成 |
| 金鑰無效或過期 | 金鑰不對、被作廢了，或填錯了 | 去 Kaggle 設定頁重新生成一把，填進設定頁 |
| 等待超時（2 小時），任務未完成 | Kaggle 那邊排隊太久或卡住了 | 過一會兒再提交一次；連續超時就檢查 Kaggle 額度是不是用完了 |
| Kaggle 執行失敗 | 腳本在 Kaggle 那邊出錯（例如下載模型失敗） | 等幾分鐘再試一次；一直失敗就看任務詳情裡的日誌最後幾行 |
| 測試連線失敗，但金鑰明明是對的 | NAS 連不到 Kaggle（網路問題） | 檢查 NAS 的網路，稍後再按一次測試連線 |
| 上傳參考圖被拒 | 圖太大（超過 10MB）、格式不對，或多圖超過 4 張 | 換張小一點的圖、只傳 jpg/png/webp，多圖最多 4 張 |
| 參考任務失敗，日誌說參考圖下載失敗 | Kaggle 那邊打不開工作台的參考圖網址 | 確認隧道域名能正常打開、參考圖網址是公網地址；本地測試時可用環境變數 REF_BASE_URL 指定公網域名 |
| 網頁打不開 | 容器沒起來 | 去飛牛 Docker 看容器狀態，點重新啟動；再看容器日誌有沒有報錯 |
